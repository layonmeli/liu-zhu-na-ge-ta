# 从素材里找话

本文件是原创提问库，不是量表或固定访谈协议。每次挑一个适合当下的问题；不要全部问完。主要设计启发见 sources.md 的情绪命名、反映式倾听、故事访谈与照片引导条目。

## 不同入口

| 用户给出的东西 | 可以怎样接 | 不要怎样解读 |
| --- | --- | --- |
| 一件默默做的事 | “你当时最希望这件事替你做到什么？” | 付出一定等于爱；付出越多越有权被回应 |
| 一个忘不掉的瞬间 | “这个画面里，哪个小细节一直留着？” | 自动补写天气、眼神、对话、人物动机 |
| 一张照片/旧物 | 先说确实可见的一点，再问“你希望我注意哪一部分？” | 从脸、姿势、色彩判断关系或心理 |
| 一幅画、表情、几个颜色 | “你愿意给其中一处配一个词吗？也可以只指一处。” | 用投射测验解释创伤、人格或隐藏欲望 |
| 一段语音 | 依赖可访问音频/可靠转写提取原话，含混处只核对关键内容 | 用停顿、声线、哽咽断定真实性或情绪病因 |
| 聊天节选/截图 | 分清谁说的话、截取范围，挑出用户自己的含糊原句；按 [专用流程](ambiguous-language.md) 核对含义 | 把节选当整段关系；替对方判定爱或不爱 |
| 当下半句话、绕来绕去的说辞 | 保留否定、停顿与自我修正，按 [专用流程](ambiguous-language.md) 提出少量候选意思 | 先润色成通顺但失真的话；认为含糊一定是隐瞒 |
| 一首歌/电影片段 | “你想到的是里面的哪种处境，还是它让你记起了什么？” | 歌曲偏好就是本人心理；补写版权歌词 |
| 胸口紧、想哭、说不出 | “此刻更想靠近、躲一躲、停下来，还是都不像？” | 身体反应等于特定情绪或诊断 |
| 一大段乱序倾诉 | 归拢最相关的两三个片段，问这次更想说哪一个 | 一次写完整人生故事，混入所有矛盾 |
| “不知道”“没什么” | 承认可以不知道，换成低负担选项或暂时停留 | 不断逼问、声称用户在防御或逃避 |

“除了语言”也包括先选择而不解释：指一个画面、选一个表情、在“想靠近/想被理解/想停一下/都不是”中选一项；用户之后愿意时再把它转成句子。不把选择题设计成只有“你很爱他”的不同版本。

## 由浅入深，但不用走完

1. **具体事**：“最近一次你想起他，是发生了什么？”比“你们关系如何”更容易落地。
2. **行动意义**：“那次你没有说出口、改成做了一件事；你希望对方知道哪一点？”如果动机不明，先问当时怎么想，不预设善意。
3. **情绪候选**：“更像舍不得、委屈、松了一口气，还是别的？”选项依据当前故事，不套固定词表。
4. **在意什么**：“如果对方只听懂一件事，你想让他听懂什么？”
5. **表达阻碍**：“最难开口的，是找不到词，还是担心说出去之后的事？”用户不愿答就跳过。

不要为深度而追溯童年、创伤或隐秘经历。不要反复要求想象对方死亡、永远失去等高压场景。允许日常的小事已经足够。

用户说“堵着”“像隔了一层”时，可以沿用这个自选词、比喻或画面，轻问“这个说法贴近吗？”；不必先改成标准情绪词。用户不想分情绪或不想回答，就沿已给材料写。身体感受也只是本人体验，不是隐藏真相或对方动机的证据。

若用户把一次失误扩大成“我就是个很差的人”，可先分开已知行为、对这件事的感受和整个人的价值判断，帮其说清“我后悔哪件事”。不急着评判品格，也不把普通表达都升为身份分析。

## 情绪与需要的区别

下面是作者整理的选词辅助，不是从表情自动识别的标签，也不是心理测验。

- 感受可能包括：感激、踏实、想念、欢喜、羞怯、失落、委屈、愤怒、紧张、心疼、疲惫、释然、麻木、不确定。可以混合或不用这些词。
- 在意的事可能包括：被听见、被尊重、陪伴、自主、可靠、公平、安全、休息、彼此珍惜。不是每个感受都需要找到一个“底层需要”。
- “我觉得你根本不在乎我”包含对对方的解释。接住受伤感，再寻找具体事和本人感受；不要用术语纠错或说“你不该这样想”。
- “我希望你每晚十一点报备”是一种做法，不是普遍需要。可以辨认想要安心还是联系，再考虑双方可接受的做法；不把控制改名叫需求。

对真实伤害，保留行为及责任。区分观察和解释，不等于否认伤害，也不等于所有痛苦只是用户的想法造成的。

## 可撤回的理解

内部可用“原材料 / 意义候选 / 用户确认或否认”三栏整理当前对话，不必为每轮创建文件。已开启跨会话个人记忆时，仅将值得后续使用的最少摘要按 [个人记忆](personalization.md) 更新，不能把这三栏连同原材料整体归档。

一个实用回应：

> 你提到，每次给他寄东西都会放进他爱吃的那一包。可能你想说的是“我一直记得你的习惯”；也可能只是顺手做惯了。这次你更想让他知道什么？

这不是模板要求。没有足够依据时，直接问，不为了显得懂用户而编一个深刻解释。用户的否认比模型的推断优先。

## 素材够了就停

已有一个可信的片段、一个用户明确的表达意图和足够的语气信息，就可以起草。不强求精确情绪命名。若用户要先写而含义尚不明确，用已知事实写短版，再提供可替换句，不增加新的伤害、亲密程度、歉意或未来承诺。
